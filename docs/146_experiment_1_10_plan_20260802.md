# Experiment 1-10 End-to-End Transport Failure Attribution 계획

## 질문

Experiment 1-9 ENFORCE-001의 client connection error/timeout/HTTP 500이 load driver, WebFlux inbound/event loop, WebClient outbound, mock dependency, 또는 이전 실행 상태에서 비롯되었는가?

## 고정 조건

- WebFlux corrected path, ENFORCE, full-path admission 320
- shared outbound pool max 400, pending max 800
- VU 200, frame/reconnect 1초, AI 2초, storage 100ms
- duration 105초, client timeout 10초
- app 2 CPU / 3 GiB, DB pool 10, 동일 fixture/auth/DB/storage contract
- retry, timeout, scheduler, queue, Base64, business pipeline 순서 유지

## 변경 조건

성능 조건은 바꾸지 않는다. 추가되는 것은 diagnostic flag와 request/transport observation뿐이다.

## 관측

- Node: fetch headers/body phase 분리, error cause chain, socket metadata, runtime/event-loop/CPU/memory/max in-flight
- WebFlux inbound: request ID별 received/committed/status/terminal/cancelled/elapsed
- WebClient: TOKEN/AI/STORAGE 고정 stage callback 및 pool/connect/response taxonomy
- Reactor Netty/Micrometer: 실제 runtime에서 존재하는 pool·event-loop·ByteBuf metric
- mock/dependency: in-flight, request count, error/restart/CPU/memory, load-stop snapshot과 drain

## 실행 순서

### Sequence A — CLEAN

각 run 전 `flux-corrected`, `experiment-mock`, 관련 dependency container를 recreate하고 health 및 5초 warm-up을 수행한다.

- `CLEAN-ENFORCE-001`
- `CLEAN-ENFORCE-002`
- `CLEAN-ENFORCE-003`

### Sequence B — REUSED

Experiment 1-9 dependency project를 재사용하고 WebFlux app만 recreate한다. health/mock idle gate와 동일 warm-up을 수행한다.

- `REUSED-ENFORCE-001`
- `REUSED-ENFORCE-002`
- `REUSED-ENFORCE-003`

각 run은 fresh application JVM, load-stop snapshot, 30초 drain, raw artifact 보존을 갖는다.

## 유효성

관측 artifact 누락, 로그·request correlation 불가, 필수 collector 실패, pre-run contamination이면 해당 run만 invalid 처리한다. 높은 error/p95/backlog/drain 잔여는 system outcome으로 보존한다.

## 판정

clean/reused 차이와 request ID 상관을 이용해 LOAD DRIVER/INBOUND, WEBFLUX INBOUND, WEBCLIENT OUTBOUND, RESPONSE DELIVERY, RUNNER STATE CONTAMINATION, UNRESOLVED 중 하나를 선택한다. 단일 run 또는 간접 지표만으로 원인을 확정하지 않는다.

## 중단 규칙

admission, pool, timeout, retry, scheduler, resource, workload를 조정하지 않는다. 결과가 기대와 달라도 추가 진단이나 MVC 실행을 시작하지 않는다.

## 결과 저장

각 run은 `experiment/results/<RUN-ID>/`에 client, application raw log, outbound/inbound diagnostic, container, database, mock, drain, provenance를 분리 보존한다. 최종 결과는 `docs/147_experiment_1_10_result_20260802.md`에만 기록한다.
