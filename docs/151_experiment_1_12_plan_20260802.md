# Experiment 1-12 Pooled Connection Reuse and TCP Close Initiator Attribution 계획

## 확인하려는 질문

AI PrematureClose 요청은 새 channel과 재사용 pooled channel 중 어디에 할당됐으며, 동일 TCP tuple에서 application과 mock 중 어느 peer가 먼저 FIN 또는 RST를 전송했는가?

## 실험 목적

Experiment 1-11이 `application outbound connection → mock HTTP handler 수신 전`으로 좁힌 실패 경계를 pooled channel lease와 TCP control packet으로 한 단계 더 귀속한다. remediation은 수행하지 않는다.

## 가설

- H1: AI PrematureClose는 `REUSED_CHANNEL`에서 발생한다.
- H2: 동일 tuple에서 mock이 application보다 먼저 FIN/RST를 전송한다.
- H3: client deadline 선행 cancellation은 AI PrematureClose와 구분되는 별도 chain이다.

## 기준 조건

- ENFORCE full-path admission 320
- shared pool max 400, pending max 800, 기존 acquire/connect/response timeout
- VU 200, initial VU 200, frame/reconnect 1초
- AI 2초, storage 100ms, duration 105초, client timeout 10초, drain 30초
- app 2 CPU/3 GiB, DB pool 10
- 동일 fixture/auth/business/DB/storage 계약

## 변경 조건

실행 semantics가 아닌 진단 정보만 추가한다.

- Reactor Netty channel identity와 observer state
- channel별 lease sequence와 NEW/REUSED 분류
- AI request ID의 channel/lease binding
- mock connection tuple lifecycle
- app/mock namespace의 SYN/FIN/RST capture sidecar
- connection 및 packet join artifact

## 동일하게 유지할 조건

pool, idle/lifetime, eviction, leasing strategy, admission, timeout, retry, scheduler, resource, workload, fixture, API body/response, TOKEN/AI/STORAGE chain을 변경하지 않는다.

## 통제하기 어려운 조건

- Docker Desktop host scheduling과 network timing
- FIN/RST가 양단 capture에 기록되는 미세한 timestamp 차이
- connection event와 packet timestamp의 clock granularity
- 단일 core에서 PrematureClose 재현 여부

## 측정 지표

- channel state별 event와 lease sequence
- AI request의 NEW/REUSED channel binding
- mock HTTP handler 수신 여부
- 정규화 socket tuple join
- 양단 SYN/FIN/RST 방향과 첫 close actor
- AI PrematureClose, HTTP 500, client timeout
- complete/incomplete connection correlation

## 성공·기각·판정 불가능 기준

- `FAILURE_ON_REUSED_CHANNEL_CONFIRMED`: 실패 request의 동일 channel이 이전 RELEASED 후 재획득됨
- `FAILURE_ON_NEW_CHANNEL_CONFIRMED`: CONNECTED 후 첫 lease에서 실패
- `MOCK_SIDE_CLOSE_CONFIRMED`: 동일 tuple의 첫 FIN/RST가 mock이고 request handler 미수신
- `APPLICATION_SIDE_CLOSE_CONFIRMED`: client deadline 선행 없이 첫 FIN/RST가 application
- `CLIENT_CANCELLATION_CHAIN`: deadline 선행 후 application close와 mock incomplete
- `NOT_REPRODUCED`: VALID core에서 AI PrematureClose와 HTTP 500이 모두 0
- 일부만 연결되면 `PARTIALLY_ATTRIBUTED`, 핵심 tuple/channel/packet이 불완전하면 `UNRESOLVED`
